# CLAUDE.md

Project rules for coding assistants (Claude Code reads this file) and for human
contributors.

## What this is

A Gladys Assistant **external integration of type `tts`**: a Node.js service
(Node 22+, ESM, no build step) that runs in its own sandboxed Docker container,
talks to Gladys through
[`@gladysassistant/integration-sdk`](https://github.com/GladysAssistant/integration-sdk-js)
(its only runtime dependency), and drives the `phonon` sub-container
(`ghcr.io/gradium-ai/ptts-openai-server`) that synthesizes the speech. It
started from the official JavaScript template.

## Commands

```bash
npm install
npm test                                  # node --test, the built-in runner
node --test test/engine.test.js           # one file
npm run lint                              # ESLint
npm run format:check                      # Prettier, as the CI runs it
npm run format                            # Prettier, fix in place
npm run sync-voices                       # refresh the voice list (needs huggingface.co)
npx github:GladysAssistant/integration-store .   # store admission checks
```

The CI runs `format:check`, `lint` and `test` on Node 22 and 24, and builds the
Docker image: run the three commands before pushing.

## Architecture

```
index.js                     builds the dependencies, connects
src/integration.js           SDK wiring: onTtsSynthesize, config updates, actions
src/engine.js                sub-container lifecycle, downloads, statuses, synthesis queue
src/hub.js                   Hugging Face downloads into the shared volume
src/voiceStore.js            the voice folder (catalog voice or Gradium custom voice)
src/gradium.js               Gradium API (custom voices)
src/phononClient.js          speech server client (MP3 stream, deadline)
src/mp3.js                   cut a partial MP3 at a frame boundary
src/models.js, src/config.js models catalog, config defaults and normalization
src/voiceLabels.js           labels of the voice select (manifest, demo page)
src/voices.catalog.json      GENERATED by scripts/sync-voices.mjs — never edit by hand
site/                        voice demo page (GitHub Pages); site/voices.json is generated
test/helpers/fakeServers.js  fake Hub, speech server and Gradium API on 127.0.0.1
```

## Rules

- **Stored keys are forever.** Model ids (`phonon-40m-fr`…), voice values
  (catalog `voice_id`, `default`, `custom`), config, action keys: the
  administrator's saved configuration refers to them.
- **The manifest voice options are generated**: change `src/voiceLabels.js` or
  the script, then run `npm run sync-voices`. `test/manifest.test.js` checks the
  options match `src/voices.catalog.json`.
- **Speech goes through the SDK**: `gladys.onTtsSynthesize` (SDK 0.16+)
  resolves the clip as `audio/mpeg;base64,...`; the SDK validates it before the
  ack. Test it with `gladys.fake.ttsSynthesize(text, language)`.
- **The container rootfs is read-only.** Write only under `/data`; the
  sub-container volume `/models` is `/data/containers/phonon/models` here.
  Never log tokens or API keys.
- **Nothing is downloaded without a model.** The integration must stay unusable
  until the administrator chooses a model: no default model.
- **Versions belong to the Release workflow** (Actions → Release). Never edit
  `version` in `package.json` or in the manifest, nor the `docker_image` tag,
  by hand. `test/manifest.test.js` checks they agree.
- **Changelog.** Every user-visible change adds a line under `## [Unreleased]`
  in `CHANGELOG.md`. Never write a version heading.
- **User-facing text** is bilingual (English and French): statuses, action
  messages, manifest texts, `docs/en.md` / `docs/fr.md`, the demo page.
- **Style.** Prettier formats, ESLint catches mistakes. Comments explain why,
  in English. Tests never touch the network.
